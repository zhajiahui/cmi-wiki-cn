<p><span style="font-family:natalya-alternate-one; font-size:650%; margin-right:-20px; margin-left:-10px;">F</span>ile structure in Denizen is important to understand since it requires the use of a few different YML files to operate properly, so let's first go over the file structure. <div class="mw-heading mw-heading4"><h4 id="denizen.jar">denizen.jar</h4></div>
<div style="margin-right:2.0em; padding:10px; font-family:camingodos-web; font-size:110%;">We have gotten a few questions about where to place the Denizen JAR file, especially from former users of Citizens 1.2, where Citizens-types went in a special folder. This is not the case for Citizens2 or Denizen. It should be treated like any other bukkit plugin and be placed in your craftbukkit/plugins/ folder. Please note that while a lot of plugins will automatically generate a folder to go along with it, Denizen does not, and this should be either created by hand and populated, or generated by copying the <a href="https://wiki.citizensnpcs.co/Denizen/0.7/Start-up_kit" title="Denizen/0.7/Start-up kit">Start-up Kit</a> with sample .yml configuration files and scripts.
</div>
<p><br/>
</p>
<div class="mw-heading mw-heading4"><h4 id="config.yml">config.yml</h4></div>
<div style="margin-right:2.0em; padding:10px; font-family:camingodos-web; font-size:110%;">
<figure class="mw-halign-right" typeof="mw:File"><a class="mw-file-description" href="https://wiki.citizensnpcs.co/File:Figure_1_-_Denizen_file_structure.png" title="Denizen File Structure"><img alt="Denizen File Structure" class="mw-file-element" decoding="async" height="331" src="https://wiki.citizensnpcs.co/images/c/c2/Figure_1_-_Denizen_file_structure.png" width="450"/></a><figcaption>Denizen File Structure</figcaption></figure>
<p>The Denizen config.yml contains nodes to alter the stock behavior and look of Denizen. You can use the config.yml to override defaults. 
</p><p>This file can be reloaded from disk to Denizen memory at any time by using <tt>/denizen reload</tt>. Some changes in the config.yml may require a restart of the server. This includes <tt>interact_delay_in_ticks</tt>, but is not limited to that config node.
</p><p>See: <a href="https://wiki.citizensnpcs.co/Denizen/0.7/config.yml" title="Denizen/0.7/config.yml">Denizen/0.7/config.yml</a> for a stock copy and explanation of all available options.
</p>
</div>
<p><br/>
</p>
<div class="mw-heading mw-heading4"><h4 id="assignments.yml">assignments.yml</h4></div>
<div style="margin-right:2.0em; padding:10px; font-family:camingodos-web; font-size:110%;">This YML is where you can define all the options and information for your Denizen NPCs. This will be explained further along in this document, but the most common information in this file is [Interact Script Assignments], [Activity Script Schedule], and [Custom Interact Texts].
<p>This file can be reloaded from disk into Denizen memory at any time by using <code>/denizen reload</code>
</p>
</div>
<p><br/>
</p>
<div class="mw-heading mw-heading4"><h4 id="saves.yml"><span style="background: white; color: red">saves.yml</span></h4></div>
<div style="margin-right:2.0em; padding:10px; font-family:camingodos-web; font-size:110%;">This file is not meant to be edited by hand, Denizen will create and populate this file automatically as needed. It stores important information such as player progression, flags, Denizen location and block bookmarks, active activity script progression and more. If you absolutely need to make changes by hand, it's best to stop the server, edit, and then restart your server, as this file is constantly being written to by Denizen which will overwrite any changes you make.
<p>To reiterate: This file saves periodically, and automatically, upon progression and a server stop, and should only be edited by hand when the server is off or Denizen is disabled.
</p>
</div>
<p><br/>
</p>
<div class="mw-heading mw-heading4"><h4 id="read-only-scripts.yml"><span style="background: white; color: red">read-only-scripts.yml</span></h4></div>
<div style="margin-right:2.0em; padding:10px; font-family:camingodos-web; font-size:110%;">This is another files that Denizen creates and should not be edited by hand. This is a combination of the files contained in the scripts folder that Denizen reads from.
<p>This file is populated on a server restart, or by using the <code>/denizen reload</code> command.
</p>
</div>
<p><br/>
</p>
<div class="mw-heading mw-heading4"><h4 id="/scripts/_folder"><span id=".2Fscripts.2F_folder"></span>/scripts/ folder</h4></div>
<div style="margin-right:2.0em; padding:10px; font-family:camingodos-web; font-size:110%;">This folder is where Denizen will read all the script information from. Upon a server load or <code>/denizen reload</code>, the files are combined and put into the read-only-scripts.yml for the Denizen to read from. This allows better organization of scripts to be maintained, since the amount of scripts can easily get into the triple digits. 
<p>The files in the plugins/Denizen/scripts/ folder can be named whatever you please, as long as they end in <code>.yml</code>. Be sure not to duplicate script names from file to file as this will cause problems. All scripts in the scripts folder are merged into <code>read-only-scripts.yml</code>, so there will be an issue if two scripts are named the same.
</p>
</div>
