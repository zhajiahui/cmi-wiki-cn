<a id="Quests.yml"></a><h1 id="questsyml">Quests.yml</h1>
<p>Quests 在位于plugins/Citizens 的quests.yml 文件中逐个定义。由于任务系统的强大和灵活性，它可能有点挑剔。特别注意间距和特殊字符的使用。 Quests.yml 应通过任何 YAML 解析器而不会出现任何错误。设置任务时出现的大多数问题都是由于格式无效造成的。</p>
<p>工具：[<a href="http://yaml-online-parser.appspot.com/">YAML 解析器</a>] 允许将 .yml 文件的内容粘贴到左侧框中。如果格式不正确，解析错误将显示在右侧面板中，指示问题。</p>
<p>使用 /citizens reload 时会重新加载 Quests.yml。</p>
<a id="Example_structure"></a><h2 id="example-structure">结构示例</h2>
<p>Quests 由不同的部分组成，如本页所述。这是大多数任务的基本流程，但并非所有节点都是必需的。</p>
<div class="highlight"><pre>"Title":
    texts:
    repeats:
    delay:
    requirements:
    initial:
    objectives:
    rewards:   
</pre></div>
<p>注意：完整任务的各个部分需要其他参数和节点。这只是一个轮廓。更多信息，深入 below:</p>

<a id="Quest_Nodes"></a><h1 id="quest-nodes">任务节点</h1>
<a id="Title"></a><h2 id="title">标题</h2>
<p>Required.</p>
<p>该文件中的每个根节点都是一个任务名称。在默认的 quest.yml 中，两个示例任务是“example”和“example2”。您将在游戏中使用此标识来标识每个任务。</p>
<p>标题是任务的第一行，用引号引起来，后跟冒号。如果是一个词，则不需要引号。</p>
<div class="highlight"><pre>"Title of quest": </pre></div>
<p>示例：游戏中将任务分配给请求者所需的命令使用此标题。</p>
<div class="highlight"><pre>/quester assign Title of quest </pre></div>
<a id="Texts"></a><h2 id="texts">文本</h2>
<p>Required.</p>
<p>在任务中，有三个必需的 texts: 描述、接受和完成。</p>
<p>当玩家选择接受任务时，描述就会发送给玩家。当玩家接受任务时，会向玩家发送接受信息，在完成任务时，会向玩家发送完成信息。</p>
<div class="highlight"><pre>texts:
    description: "Description text."
    acceptance: "Acceptance text."
    completion: "Completion text."</pre></div>
<p>默认文本为白色。特殊字符组合可用于格式化文本。请参阅：<a href="1.x-message-formatting.md" title="1.x/Message Formatting">1.x/消息格式</a> 和 <a href="https://wiki.citizensnpcs.co/index.php?title=1.x/Quest_Text_Formatting_Tips&amp;action=edit&amp;redlink=1" title="1.x/Quest Text Formatting Tips (page does not exist)">1.x/Quest 文本格式提示</a></p>
<a id="Repeats"></a><h2 id="repeats">重复</h2>
<p>可选。如果未设置，则默认为 0。</p>
<p>repeats: 选项允许您设置重复任务的次数限制。</p>
<div class="highlight"><pre>repeats: 6    # Quest can be repeated 6 times.  </pre></div>
<p>使用 -1 表示无限重复，使用 0 表示不重复。</p>
<a id="Delay"></a><h2 id="delay">延迟</h2>
<p>可选。如果未设置，默认值为 0。</p>
<p>delay: 选项允许您指定允许重新接受任务之前的时间（以分钟为单位）。</p>
<div class="highlight"><pre>delay: 10     # Allows the quest, if allowed, to be repeated 10 minutes after completing it.</pre></div>
<a id="Requirements"></a><h2 id="requirements">条件</h2>
<p>Optional.</p>
<p>requirements: 节点在允许玩家执行任务之前检查条件。需求类型可以是物品、任务、时间、金钱、健康、等级或权限。</p>
<p>另请参阅：<a href="1.x-list-of-requirement-node-types.md" title="1.x/List of Requirement node types">1.x/需求节点类型列表</a></p>
<p><em>- aufdemrand: 的注释需要仔细检查每种类型以确认它们有效。我确信任务、金钱和物品的工作。我假设其他人。</em></p>
<div class="highlight"><pre>requirements:
    '0':
        type: item    # Requires item(s) when accepting.
        id: 15        # iron_ore
        amount: 15   
        take: true    # take the 15 iron_ore, set to false to leave items on player.
    '1':
        type: quest   # Requires a quest be completed prior.
        quest: "example1"
</pre></div>
<p>您可能有多项要求，也可能只有一项要求。</p>
<a id="Initial"></a><h2 id="initial">初始</h2>
<ul>
<li>注意：需要 Citizens 1.1.4 或更高版本。</li>
</ul>
<p>Optional.</p>
<p>一旦满足允许玩家执行任务的条件，initial: 节点就会触发。许多实际用途都可以用于此目的，但其中一些可能是 be:</p>
<ul>
<li>为玩家提供一些装备来开始任务。</li>
<li>向玩家提供在任务中使用的物品。</li>
<li>给予玩家特殊等级或许可。</li>
<li>执行服务器命令。</li>
<li>生成 NPC 贴身护卫，协助执行任务的玩家。</li>
</ul>
<p>初始类型可以是物品、任务、时间、金钱、健康、等级或权限。</p>
<p>另请参阅：<a href="1.x-list-of-initial-node-types.md" title="1.x/List of Initial node types">1.x/初始节点类型列表</a></p>
<p><em>- aufdemrand: 的注释需要仔细检查每种类型以确认它们有效。我确信金钱和物品的工作。我假设其他人。</em></p>
<div class="highlight"><pre>initial:
    '0':
        type: item     # Gives an item when conditions are met.
        id: 268        # wooden_sword
        amount: 1   
        take: false    # Optional. By default, take: is false.
</pre></div>
<p>您可能有多个条目，也可能只有一个。</p>
<a id="Rewards"></a><h2 id="rewards">奖励</h2>
<p>Optional.</p>
<p>rewards:节点用于告诉询问者在满足条件时奖励玩家什么。如果所有目标都完成，则触发 rewards: 节点。</p>
<p>另请参阅：<a href="1.x-list-of-rewards-node-types.md" title="1.x/List of Rewards node types">1.x/奖励节点类型列表</a></p>
<div class="highlight"><pre>rewards:
    '0':
        type: item    # Rewards an item
        id: 15        # iron_ore
        amount: 30
    '1':
        type: quest   # Rewards a quest.  This quest will start immediately.
        quest: "Part II"
</pre></div>
<p>您可能有多种奖励，也可能只有一种。奖励也可以细分为目标，以在目标完成时奖励玩家。格式是一样的。</p>
<a id="Objectives"></a><h2 id="objectives">目标</h2>
<p>这部分是任务文件的重点。目标告诉任务 NPC需要完成什么才能完成任务。可用的目标包括狩猎、交付、摧毁等等。它们可以一起使用，使任务变得简单或详细，如您所愿。</p>
<p>另请参阅：<a href="1.x-list-of-objective-node-types.md" title="1.x/List of Objective node types">1.x/目标节点类型列表</a></p>
<a id="Basic_objective_structure"></a><h3 id="basic-objective-structure">基本目标结构</h3>
<p>目标由子目标组成。在下面的示例中，要完成任务，目标 0 必须先完成 3 个子目标，然后玩家才能尝试完成目标 1。当目标 1 中的子目标完成时，任务就会完成。</p>
<div class="highlight"><pre>    objectives:
        '0':
            '0':
                type:
            '1':
                type:
            '2':
                type:
        '1':
            '0':
                type:
</pre></div>
<p>如果您的任务只有一个目标，则它仍必须嵌套为子目标。示例 below:</p>
<div class="highlight"><pre>    objectives:
        '0':
            '0':
                type:
</pre></div>
<p><em>注：以上2个例子只是目标结构的一个概述。为了成功完成任务，需要定义更多节点。继续阅读。</em></p>
<a id="Breakdown_of_an_objective"></a><h3 id="breakdown-of-an-objective">目标分解</h3>
<p>子目标包含类型及其节点。使用<a href="1.x-list-of-objective-node-types.md" title="1.x/List of Objective node types">1.x/目标节点类型列表</a>，您可以使用各种类型来控制任务流程。以下是使用搜寻目标和交付目标的示例。子目标可以按任何顺序完成。</p>
<div class="highlight"><pre>'0':
    '0':
        type: hunt          # Type set to hunt objective
        string: zombie     # Type of monster to hunt is set to Zombie.
        amount: 2           # Amount of monsters required to hunt.
        optional: False     # Quest sub-objective is required to complete the quest.
        message: "Pesky zombies slaughtered."    # Message displayed when sub-objective is completed.
    '1':
        type: delivery      # Type of second sub-objective set to delivery.
        materialid: 341     # Slimeballs.
        amount: 6           # 6 items must be on hand to complete sub-objective.
        npcdestination: 2   # NPC # that the items must be taken to.
        optional: True      # Sub-objective not required, is optional.
        message: "Slimeballs delivered."    # Message displayed when second sub-objective is completed.
</pre></div>
<a id="A_reward_inside_a_sub-objective"></a><h3 id="a-reward-inside-a-sub-objective">子目标内的奖励</h3>
<p>正如奖励节点部分中提到的，奖励也可以在完成子目标时触发。它们应该嵌套在子目标内，如示例 following:</p>
<div class="highlight"><pre>'0':
    type: move distance     # Player must move specified amount of blocks
    amount: 6               # 6 blocks to be exact
    optional: False
    message: "You received a bow and some arrows! Sweet!"
    rewards:
        '0':
             type: item     # Reward type set to item
             id: 261        #  Bow
             amount: 1
        '1':
             type: item     # Second reward type also an item
             id: 262        # Arrow
             amount: 64     # 1 stack</pre></div>
