<p><strong>Builder</strong> 是 Citizens 2.0 <a href="characters.md" title="Characters">性格特征</a>，它使 NPCs 能够：</p>
<ul>
<li>逐块构建 MCEdit/Worldedit 结构文件。</li>
<li>重建一个区域，修复任何已更改的内容。</li>
<li>在建造之前向玩家收集所需的材料。</li>
</ul>

<a id="Installation"></a><h2 id="installation">安装</h2>
<ul>
<li>安装 Citizens 2</li>
<li>将 Builder.jar 文件放在 /plugins 目录中。</li>
<li>将 .schematic 文件放在 /plugins/Builder/schematics/ 中</li>
<li>启动服务器</li>
<li>创建 NPC 并赋予 Builder 特征。</li>
</ul>
<div class="highlight"><pre>/npc create Bob --trait builder
</pre></div>
<p>或</p>
<div class="highlight"><pre>/npc create Bob
/trait builder
</pre></div>
<a id="Permissions"></a><h2 id="permissions">权限</h2>
<ul>
<li><em>builder.</em>* 授予所有 Builder 权限。</li>
<li><em>builder.[command]</em> 授予对[命令]的访问权限。</li>
<li><em>builder.donate</em> 允许玩家在供应模式下向建造者捐款（对于锁定创造模式玩家很有用）</li>
</ul>
<a id="Configuration"></a><h2 id="configuration">配置</h2>
<p>参见 <a href="builder-configuration.md" title="Builder/Configuration">配置</a>。</p>
<p>如果 Builder 尚不存在，则将创建 <em>Builder/config.yml</em>。如果添加了新选项，请务必检查配置页面。</p>
<a id="Commands"></a><h2 id="commands">命令</h2>
<p>所有命令都可以在选定的 NPC 上运行，如图所示 (<code>/builder [command]</code>)，或者在带有 <code>/builder [npcid] [command]</code> 的目标 NPC 上运行。</p>
<p><strong>/builder list</strong> - 列出已配置结构文件文件夹中的所有可用结构文件。不需要选择建造商。</p>
<p><strong>/builder load [schematic]</strong> - 加载 .schematic 文件。只需使用结构文件的名称即可。
示例</p>
<div class="highlight"><pre>/builder load house
</pre></div>
<p><strong>/builder origin</strong> - 将构建器项目的原点设置为构建器的当前位置。允许您在同一地点重建。如果未设置，构建器将始终从当前位置开始。</p>
<p><strong>/builder origin clear</strong> - 清除保存的构建原点。</p>
<p><strong>/builder origin schematic</strong> - 将构建器项目的原点设置为加载结构文件的原点。最适用于使用 worldedit 从构建者的世界创建的结构文件。</p>
<p><strong>/builder origin me</strong> - 将构建器项目的原点设置为玩家的位置。无法从控制台运行。</p>
<p><strong>/builder origin current</strong> - 将构建器项目的原点设置为当前正在构建的项目的原点。如果您在开始构建之前忘记设置原点，并且需要取消它以稍后恢复，请使用此选项。</p>
<p><strong>/builder origin x,y,z</strong> - 将构建器项目的原点设置为构建器当前世界的位置 x,y,z。</p>
<p><strong>/builder mark (item)</strong> - 在足迹的 4 个角放置一个块，然后返回原点，这样您就可以看到它将在哪里构建。您可以指定要使用的项目，但 config.yml 中必须允许该项目。如果未指定任何项目，则配置中列表中的第一项为默认值。如果缺少配置，构建器将使用 GLASS。</p>
<p><strong>/builder timeout [value]</strong> - 设置块之间的最长时间（以秒为单位）。有效值为 0.1 - 2000000.0。默认值为 2.0。默认值可以在 config.yml 中更改。</p>
<p><strong>/builder build (option1) (option2) ... etc</strong> - 开始构建结构文件。该命令需要几个可选参数。顺序并不重要。您可以向此命令添加以下内容：</p>
<ul>
<li>线性 - 从北向南建造</li>
<li>反向线性 - 从南到北构建</li>
<li>sprial：从内向外建造（默认值，无须指定）。</li>
<li>反向螺旋 - 由外向内构建。</li>
<li>挖掘 - 建造者将在开始放置块之前清除块的区域。</li>
<li>layers:# - 构建器将一次构建#层数，默认为1。</li>
<li>yoffset:# - 建造者将从设定的起始位置向上或向下开始建造指定数量的方块。</li>
<li>groupall - 构建器将立即构建所有一组材料，而不是逐层构建。</li>
<li>ignoreair - 建造者不会放置空气块。 （用于构建现有结构，如果与挖掘一起使用则毫无意义）</li>
<li>ignoreliquid - 建造者不会放置熔岩或水块。 （如果结构文件底部有不受约束的液体，则使用。）</li>
<li>onstart:Task - 构建器将在构建开始时运行 <a href="denizen.md" title="Denizen">Denizen</a> 任务脚本（材料收集后）。见<a href="#Advanced_Usage">#高级用法</a></li>
<li>oncomplete:Task - 构建器将在构建完成时运行 <a href="denizen.md" title="Denizen">Denizen</a> 任务脚本。见<a href="#Advanced_Usage">#高级用法</a></li>
<li>oncancel:Task - 构建器将在取消构建时运行 <a href="denizen.md" title="Denizen">Denizen</a> 任务脚本。见<a href="#Advanced_Usage">#高级用法</a></li>
<li>静默 - 构建器不会向命令发送者发送完成/错误消息。</li>
</ul>
<p>Examples:</p>
<div class="highlight"><pre>/builder build
/builder build excavate reverselinear yoffset:-3
/builder build ignoreair ignoreliquid oncomplete:Celebrate
/builder build groupall layers:3
</pre></div>
<p><strong>/builder cancel</strong> - 取消构建作业。</p>
<p><strong>/builder info</strong> - 查看 Builder 加载的结构文件名称和大小，以及构建器的选项和状态。</p>
<p><strong>/builder survey (excavate)</strong> - 显示在当前位置构建所需的所有块类型/数量的列表。如果使用挖掘，则指定挖掘以显示材料列表。不显示水或熔岩。</p>
<p><strong>/builder supply true|false</strong> 设置建造者在开始建造之前是否需要给材料。见<a href="#Supply_Mode">#供应模式</a></p>
<p><strong>/builder hold true|false</strong> 设置建造者是否保留他正在放置的物品（仅为了与 <a href="sentry.md" title="Sentry">Sentry</a> 等其他插件兼容而关闭）</p>
<p><strong>/builder reload</strong> - 从构建器 config.yml 重新加载选项</p>
<p><strong>/builder help</strong> - 显示帮助。</p>
<a id="Usage"></a><h2 id="usage">用途</h2>
<ul>
<li>.schematic 文件应放置在 <em>/plugins/Builder/schematics/</em> 目录中。该目录可以在config.yml中配置</li>
<li>在调用 <strong>建造</strong> 之前，将构建器定位，或将构建器的 <strong>起源</strong> 设置为要构建的脚点的 <em>中心</em>。结构文件的尺寸在加载时显示。</li>
<li>如果您设置了 Origin，则可以取消构建并稍后恢复构建。如果您忘记了，可以在构建开始后使用 <code>/builder origin current</code> 设置原点。</li>
<li>不要尝试使用挖掘选项恢复构建！</li>
<li>构建器将忽略结构文件对象下方的任何空白空间，以便它始终停留在构建器开始的地面上。如果要在原点上方或下方构建，请使用 yoffset: 构建选项。</li>
<li>构建器不会尝试替换已经正确设置的块，这意味着您可以使用构建器快速“恢复”他之前构建的任何已更改的块。</li>
<li>设置构建器来维护现有的 building:<ul>
<li>使用 worldedit 选择建筑物并将其保存为示意图。</li>
<li>将结构文件复制到构建器的结构文件目录中。</li>
<li>将结构文件加载到构建器并调用 <code>/builder origin schematic</code>。</li>
<li>调用 /builder build ，构建器将放置任何丢失的块或销毁新的块。</li>
</ul>
</li>
<li>导轨和分配器可能未正确放置。 （嘿，这是建筑，而不是工程。）</li>
<li>默认情况下，NPCs 在其块卸载时消失。可以在 Citizens2 config.yml 中更改此行为，如果您希望构建器继续无人值守工作，建议您这样做。</li>
</ul>
<a id="Supply_Mode"></a><h2 id="supply-mode">供货方式</h2>
<p>如果 Builder 设置为需要建筑材料（使用 <em>/builder supply true</em>），则当 <em>/builder build</em> 被调用时，他将进入供应模式。当供应模式启动时，Builder 将勘察建筑工地并生成开始建筑所需材料的列表。玩家必须向建造者提供这些材料才能开始建造。</p>
<p>在供应模式下：</p>
<ul>
<li>空手右键点击Builder，即可查看仍需要的材料列表。</li>
<li>右键点击 Builder 与任何块或项目，看看他是否需要它。如果他这样做了，他会告诉你他还需要多少。</li>
<li>点击所需材料后，在几秒钟内再次右键点击，将其交给Builder。</li>
<li>收到材料后，Builder 会说他总共还需要多少块才能开始，或者如果他拥有一切，他将开始建造。</li>
</ul>
<p>required:是什么材料</p>
<ul>
<li>默认情况下，所有块都需要其正常的掉落类型（i.e。蜘蛛网需要字符串）</li>
<li>可以通过 \Builder 文件夹中的“supply.txt”文件覆盖此行为。</li>
<li>每行包含结构文件中块的 Item ID 以及所需块/Item 的 ItemID。</li>
<li>您可以选择指定每个源块所需的块/项目的数量。</li>
<li>将所需的项目 ID 设置为 0 将不会在需求中包含该源块。</li>
</ul>

<p>目前，所有块仅在项目 ID 上进行匹配。这个means:</p>

<a id="Advanced_Usage"></a><h2 id="advanced-usage">高级用法</h2>
<ul>
<li>Builder 可以设置为在构建开始、完成或取消时运行 <a href="denizen.md" title="Denizen">Denizen</a> 任务脚本。</li>
<li>NPC 必须同时具有 Builder 和 <a href="denizen.md" title="Denizen">Denizen</a> 特征。</li>
<li>致电 <code>/builder build</code> 使用可选修饰符<ul>
<li><code>onstart:TaskName</code></li>
<li><code>oncomplete:TaskName</code></li>
<li><code>oncancel:TaskName</code>.</li>
</ul>
</li>
</ul>
<p>Example:</p>
<div class="highlight"><pre>/builder build oncomplete:DespawnTask oncancel:AnnounceTask
</pre></div>
<ul>
<li>Builder 还可以在 3 个指定事件中运行 <a href="https://wiki.citizensnpcs.co/index.php?title=Denizen_Actions&amp;action=edit&amp;redlink=1" title="Denizen Actions (page does not exist)">Denizen 行动</a>。将以下内容添加到 NPC 的操作中：</li>
<li>“构建开始”</li>
<li>“构建完成”</li>
<li>“建立取消”</li>
</ul>
<p>Example:</p>
<pre>BuilderAssignment:
  type: assignment
  actions:
    on Build Start:
      - ANNOUNCE "Let's do this!"
    on Build Complete:
      - ANNOUNCE "I have finished!"
</pre>
<p>有关 Denizen 和 Builder 的更复杂示例，请参阅 <a href="builder-builder-and-denizen.md" title="Builder/Builder and Denizen">Builder 和 Denizen 示例</a></p>
<a id="FAQ"></a><h2 id="faq">FAQ</h2>
<p>问：如何在一个项目上使用多个构建器？</p>
<p>答：您可以在一个项目中使用最多 4 个构建器，方法是为它们提供相同的结构文件和起源，但构建模式不同。您还可以使用 WorldEdit 或 MCEdit 手动将结构文件拆分为多个部分。</p>
<p>问：怎样才能让建造者走得更快？</p>
<p>A：使用/builder timeout命令设置块之间的最大时间。您还可以使用“/npc speed”让建造者走得更快</p>
