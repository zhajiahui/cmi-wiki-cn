# 4.0.X 更新记录

# 4.0.0 {#400}

## 4.0 条件系统重做 {#40-condition-system-revamp}

MythicMobs 的条件系统进行了一些相当不错的改动，希望大家也像我们一样，觉得它有趣又实用！我们花了不少精力，几乎将其“重做”了一遍，对它带来的新能力非常满意。

之前在 MythicMobs 中可用的条件没有任何一个被移除——事实上它们全都还在，我们甚至又新增了不少条件。这次改动最重要的部分，是系统如今的工作方式以及它提供的新可能。

旧条件非常基础，只会对生物和/或生物的目标进行判断。新系统现在按三种方式之一工作：对技能的施法者、技能的目标，或触发技能的实体进行判断。与技能机制类似，条件现在也分为实体条件和位置条件。

**注意：**仍可通过改用 "LegacyConditions:" 来使用旧条件。例如：新版 targetlineinsight 的写法如下：

```
  TargetConditions:
  - lineofsight true
```

旧版仍然可以这样使用：

```
  LegacyConditions:
  - targetlineofsight true
```

继续阅读，了解各类条件的详细使用方法。

### 格式 {#format}

条件的格式现已更新。大多数旧条件应当仍能像以前一样工作，但现在也可以选择在条件中包含多个选项和动作。

新格式的写法如下：

```
Conditions:
- condition [variable]
- condition [variable] [action]
- condition [variable] [action] [action_variable]
- condition{variable1=value;variable2=value} [action] [action_variable]
```

旧格式在大多数情况下仍然有效，大部分技能应该不会失效。不过，新格式也支持能够判断多个变量的更高级条件。

以下都是新格式的有效示例：

```
Conditions:
- day required
- stance defensive power 0.5
- stance{stance=defensive} power 0.5
- score{objective=test;value=>20} cancel
- haspotioneffect{type=POISON;level=>0;duration=0 to 100} true
```

#### 条件 {#conditions}

技能的 "Conditions" 字段现在始终只对施法者进行条件判断。条件不满足时，技能就不会触发。

#### TargetConditions {#targetconditions}

技能的 "TargetConditions" 字段使技能仅对满足条件的目标执行。技能继承的所有目标都会按条件筛选，不满足条件的目标会从技能的目标列表中移除。

Example:

```
# Mob
TestMob:
  Type: ZOMBIE
  Skills:
  - skill{s=Flare} @PlayersInRadius{r=20}

# Skill
Flare:
  TargetConditions:
  - lineofsight true
  Skills:
  - ignite{d=10}
```

此示例中的技能只会点燃处于生物视线内的目标。

#### TriggerConditions {#triggerconditions}

技能的 "TriggerConditions" 字段始终只对触发技能的实体进行条件判断。条件不满足时，技能就不会触发。

```
Skill:
  TriggerConditions:
  - entitytype ZOMBIE true
  Skills:
  ...
```

此示例技能仅在触发实体是僵尸时才会施放。

#### 条件动作 {#condition-actions}

条件动作是一项新功能，可根据条件执行额外操作。以前条件始终是“必须满足的要求”，现在可以为条件指定其他作用。

以下是新增的动作列表：

- **required**（或 **true**）*（默认）* - 必须满足此条件，技能才会运行。
- **cancel**（或 **false**）- 如果满足此条件，技能就不会运行。
- **power [power multiplier]** - 修改技能的强度（例如 power 2.0 会使技能强度翻倍）
- **cast [skill]** - 尚未实现：满足条件时，额外施放一个技能。
- **castinstead [skill]** - 尚未实现：满足条件时，改为施放另一个技能。

### 条件 {#conditions-2}

#### 新增：Altitude 条件 {#new-altitude-condition}

* 检测目标距地面的高度。  
* 可以是单个数值、一个范围（20-40），或 >10 <5 等。

#### 新增：Crouching 条件 {#new-crouching-condition}

* 检测实体（必须是玩家）是否正在潜行。

#### 新增：Distance 条件 {#new-distance-condition}

* 检查目标与施法实体之间的距离。

#### 新增：EntityType 条件 {#new-entitytype-condition}

* 检测目标是否符合 entitytype。  
示例：

```
  - entitytype PLAYER true
```

#### 新增：FallSpeed 条件 {#new-fallspeed-condition}

* 检测生物的下落速度。可以是正值或负值。（用于跳跃。）
* 可以是单个数值、一个范围（20-40），或 >10 <5 等。
示例：

```
- fallspeed{speed=>0.7845} true
```

#### 新增：Gliding 条件 {#new-gliding-condition}

* 检查目标是否正在使用鞘翅滑翔。

#### 新增：HasPotionEffect 条件 {#new-haspotioneffect-condition}

* 检查目标是否具有该药水效果。  
* 可以指定多个选项，包括效果等级和持续时间。
示例：

```
- haspotioneffect{type=POISON;level=>1;duration=0 to 100} true
```

仅当目标拥有 2 级或更高等级的中毒效果，且持续时间为 0 到 100 刻时才会生效。

#### 新增：HasTag 条件 {#new-hastag-condition}

* 检查目标的记分板标签。可使用 [Add Tag](../skills/mechanics/addtag.md) 机制添加。
示例：

```
  - hastag{tag=Test} true
```

#### 新增：LineOfSight 条件 {#new-lineofsight-condition}

* 检查实体是否能看见其目标/中间是否没有方块阻挡。

#### 新增：OnGround 条件 {#new-onground-condition}

* 检查施法者是否在地面上。含义很直观。

#### 新增：Score 条件 {#new-score-condition}

* 取代旧的 targetscore 和 mobscore 机制。  
* 可以是单个数值、一个范围（20-40），或 >10 <5 等。  
示例：

```
- score{objective=test;v=>20} true
```

仅当目标的 "test" 计分项数值大于 20 时才会运行。

## 技能 {#skills}

### 技能机制 {#mechanics}

#### 新增：AddTag {#new-addtag}

为目标实体添加一个记分板标签。

#### 新增：CancelEvent {#new-cancelevent}

[CancelEvent](../skills/mechanics/cancelevent.md) 会取消触发该技能的事件。

此机制要正确执行，必须满足以下几项重要要求：

- 必须在生物的技能列表中，为此机制（或调用链中最先通向它的技能）设置 sync=true。
- 在执行此机制之前不得有任何“延迟”（不得使用 delay 机制，也不得使用弹射物等其他带延迟的内容）
- 仅适用于特定且有意义的触发器（适用于 onDamaged、onAttack 等，但不适用于 onDeath！（~onDeath 已于 5.3.0 The Pande Update 中添加）

#### 新增：Lunge {#new-lunge}

使施法者朝目标加速。

#### 新增：RemoveTag {#new-removetag}

移除目标实体的一个记分板标签。

#### 新增：SetHealth {#new-sethealth}

#### 新增：SetMaxHealth {#new-setmaxhealth}

#### 新增：SetOwner {#new-setowner}

#### 新增：SudoSkill {#new-sudoskill}

SudoSkill 机制允许强制目标实体“施放”一个 MythicMobs 技能。该技能会继承堆栈中先前父技能的目标，甚至可以强制玩家使用 MythicMobs 技能。

#### Projectile {#projectile}

- **fromOrigin** 现在默认为 false。

#### Shoot {#shoot}

- 新增 **startYoffset** 属性。

### 目标选择器 {#targeters}

- 为目标新增 **owner**。

#### 目标过滤器 {#target-filters}

- 为目标筛选器新增 **samefaction**。

### 自定义技能机制 {#custom-mechanics}

开发者现在可以使用 **MythicMechanicLoadEvent** 在运行时向 MythicMobs 添加自定义机制。示例将发布在手册和 API 论坛中。

### 自定义条件 {#custom-conditions}

开发者现在可以使用 **MythicConditionLoadEvent** 在运行时向 MythicMobs 添加自定义机制。示例将发布在手册和 API 论坛中。

### 新增 API 事件 {#new-api-events}

- **MythicConditionLoadEvent** - 启动/重载时，会针对插件中引用的每个自定义条件调用。
- **MythicMechanicLoadEvent** - 启动/重载时，会针对插件中引用的每个自定义条件调用。
- **MythicReloadedEvent** - 在 MythicMobs 完成重载后调用
